# Automatic publishing for @unemployerr

The current configuration uses **local Ollama**, prefers light Hinglish, enables unattended processing and requests public uploads to channel `UCh9aBTHwc9QyIhe5SflYtBQ`. Anthropic code and its dependency have been removed. No LLM API key is required.

## One-time YouTube connection

1. Open [Google Cloud Console](https://console.cloud.google.com/), create/select a project, and enable **YouTube Data API v3**.
2. Configure the OAuth consent screen. If the app is in Testing, add the Google account that owns/manages @unemployerr as a test user.
3. Create an OAuth client using application type **Desktop app** and download its JSON.
4. Save the JSON at `M:\opportunity-shorts\opportunity-shorts\secrets\client_secret.json`. Do not paste passwords, tokens or recovery codes into chat.
5. That path is detected by default. For a different path, set `YOUTUBE_CLIENT_SECRETS_FILE` in `.env` or the environment.
6. From the inner project folder, run `python -m shorts auth`. Google opens a browser consent page; select the account/Brand Account corresponding to @unemployerr. The application verifies the exact channel ID. Upload and read-only YouTube access are requested; read-only access checks channel identity and recovers accepted uploads after a lost response.

Authorization is the unavoidable one-time account connection, not an approval for each video. Refresh tokens are stored locally at `secrets/youtube_token.json`; expired/revoked consent may need renewed sign-in. For long-running use, finish Google's applicable consent-screen production setup rather than relying on short-lived testing credentials. Never commit secrets.

The current [videos.insert reference](https://developers.google.com/youtube/v3/docs/videos/insert) explicitly says uploads from unverified API projects are not restricted to private viewing. Other older Google reference pages retain the previous restriction. Actual publishing and visibility must be verified on the connected channel. The configured daily cap is three attempts, regardless of Google's separate project quota.

## Local model and narration

The installed qwen3:8b failed to load on this computer due to insufficient memory. A smaller `qwen3:1.7b` is configured with a 4,096-token context. Use:

```powershell
ollama pull qwen3:1.7b
ollama list
python -m shorts doctor
```

Leave Ollama running and provide enough free RAM for the model. The pull was started during setup; downloading alone does not prove that inference works. `OLLAMA_MODEL` and `OLLAMA_BASE_URL` override YAML if set. Generation failures defer the item instead of silently publishing repetitive template output. An explicit `llm.provider: template` exists for offline tests; production uses Ollama.

Hinglish is a prompting preference with clear English permitted if needed. Current narration uses Indian-English Edge TTS voices. Natural Hindi pronunciation and script quality cannot be guaranteed solely by automatic numeric checks. Future Hindi voices or human-recorded narration can improve this if the current voice is insufficient. Edge TTS still needs internet, but no user-supplied API key.

## Worker

The **OpportunityShortsWorker** current-user Windows scheduled task is installed. It starts at user login, runs with ordinary user privileges, restarts after failures, and uses `pythonw.exe` when available to avoid a console window. A process lock prevents two daemons from running together.

- Collection: every six hours.
- Generation: keeps a bounded queue of up to three videos, selected by collector score with duplicate company/role filtering.
- Publishing: checks due schedules every minute; initial IST slots are 08:00, 13:00, 19:00.
- Failed builds: wait one hour before retry; other listings can proceed. Unavailable/missing models are checked before processing the queue.
- Listings and rendered videos require **no human approval** in automatic mode. Rejected items stay rejected.
- Automatically checks source flags/deadlines, suspicious listings, script fields/claims/links, layout, duration, stale facts, daily limits and duplicates. These checks are not per-video permission prompts and do not establish every prose claim as true.
- On changed facts or a changed configured generator, the video is regenerated. Old template video manifests are not assumed to have been generated by Ollama.
- Uncertain uploads are searched in the authorized channel's latest uploads for an exact title/description match. A unique match is reconciled automatically. An unresolved or ambiguous attempt is held rather than creating duplicate videos; other opportunities continue.

Logs: `data/opportunities.worker.log`; hidden-process startup diagnostics also go to `data/worker-console.log`. The scheduled task launches `scripts/worker.py`, which sets the project directory and captures output before importing the pipeline. Its running state and startup log were verified. This is a local Windows worker, not cloud hosting: the computer must remain awake, online and logged in. Ollama must be running. Windows logout shuts down the interactive worker; login starts it again. No YouTube credentials have been supplied and no real publishing has been verified yet.

Verification: **96 tests passed, 6 historical placeholders skipped**. Coverage includes local Ollama request/response handling, invalid output rejection, unattended build/upload, scheduling idempotency, changed facts/models, failed-item deferral, duplicate ambiguity and lost-response recovery. Live local-model generation remains unverified because of memory pressure and the pending smaller-model download; these tests use mocked model/upload responses.

```powershell
# Foreground alternative; the installed task already owns the worker lock:
python -m shorts daemon
# One cycle without publication:
python -m shorts run-daily
# One cycle with publication:
python -m shorts run-daily --upload
# Stop/start the installed worker:
Stop-ScheduledTask -TaskName OpportunityShortsWorker
Start-ScheduledTask -TaskName OpportunityShortsWorker
# Remove autostart if desired:
Unregister-ScheduledTask -TaskName OpportunityShortsWorker -Confirm:$false
```

To return to the optional manual workflow, stop the worker and set `automation.enabled: false` in `config/shorts.yaml`; then listing and video approvals apply again. The dashboard remains available for observation, script edits, rejected-item management and exports.
